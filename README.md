## 🖥 پنل وب

آدرس پنل = آدرس Worker یا Railway + `/panel` (مثلا `https://xxx.workers.dev/panel`). فارسی و راست‌به‌چین، تم تیره و سازگار با موبایل (می‌تونی از منوی مرورگر به صفحه‌ی اصلی گوشی اضافه‌اش کنی).

### ورود
1. **از داخل ربات:** به‌عنوان ادمین دستور `/panel` رو بفرست؛ لینک ورود **یک‌بار مصرف و ۵ دقیقه‌ای** می‌گیری.
2. **با رمز:** متغیر `PANEL_PASSWORD` رو ست کن و رمز رو توی صفحه‌ی ورود بزن (بعد از ۸ تلاش اشتباه، ۱۰ دقیقه قفل میشه).

نشست ۷ روز اعتبار داره. برای باطل‌کردن همه‌ی نشست‌ها، `SESSION_SECRET` رو عوض کن (یا اگه نذاشتی، `PANEL_PASSWORD`).

### بخش‌ها
| بخش | کارها |
|---|---|
| **داشبورد** | فروش امروز/۷ و ۳۰ روز، کاربران، نمودار ۱۴ روزه، رسیدهای در انتظار (تایید/رد سریع)، هشدار موجودی و مصرف منابع |
| **پنل‌های VPN** | افزودن/ویرایش Marzban، PasarGuard و 3x-ui، تست اتصال |
| **محصولات و تعرفه‌ها** | پلن ثابت، حجم دلخواه، تست رایگان، دسته‌بندی، انبار کانفیگ (افزودن گروهی) |
| **رسیدها و سفارش‌ها** | فیلتر و جستجو، دیدن عکس رسید، تایید (تحویل خودکار سرویس) و رد |
| **بهینه‌ساز و مصرف** | آمار کش و KV؛ روی Cloudflare مصرف Worker/KV/D1؛ روی Railway منابع سرور و صف درخواست‌ها |
| **کاربران و کیف‌پول** | جستجو، مسدود/آزاد، افزایش/کاهش موجودی (با اطلاع به کاربر)، پیام تکی، **پیام همگانی** |
| **بکاپ و بازیابی** | دانلود JSON، ارسال به تلگرام، بکاپ خودکار، بازیابی (جایگزینی یا ادغام) |
| **سیستم و استقرار** | وضعیت ربات و وبهوک، تنظیم/حذف وبهوک، چک‌لیست متغیرها |
| **تنظیمات ربات** | شماره کارت، متن پشتیبانی/آموزش، درصد زیرمجموعه، دکمه‌ها و رنگ‌ها، قوانین، گردونه، کانال اجباری، گروه گزارش |

### ⚡ بهینه‌ساز
- **هر دو پلتفرم:** همه‌ی تنظیمات ربات با «یک» کوئری خونده و ۱۵ ثانیه توی حافظه کش میشه (به‌جای یک کوئری برای هر تنظیم). اگه **KV** وصل باشه، یه نسخه‌ی مشترک هم اونجا هست که فقط موقع تغییر تنظیمات نوشته میشه (سقف نوشتن KV پلن رایگان ۱۰۰۰ بار در روزه). KV **اختیاریه**.
- **فقط Railway:** صف نرخ تلگرام (~۲۵ پیام در ثانیه + فاصله برای هر چت) با تلاش مجدد خودکار روی خطای 429، حذف آپدیت تکراری تلگرام، صف ترتیبی برای هر کاربر، ادغام درخواست‌های GET هم‌زمان و تایم‌اوت ۲۵ ثانیه‌ای.

### 💾 بکاپ و بازیابی
- فایل بکاپ شامل همه‌ی جدول‌ها (کاربران، سفارش‌ها، محصولات، کانفیگ‌ها، پنل‌ها، تنظیمات و ...) است. **رمز پنل‌های VPN هم داخلشه؛ جای امن نگهش دار.**
- قبل از بازیابی، ابتدا یک بکاپ ایمنی از وضعیت فعلی دانلود میشه. در حالت «جایگزینی کامل» داده‌ی فعلی پاک میشه و در «ادغام» ردیف‌های هم‌شناسه بازنویسی میشن. تا پایان بازیابی صفحه رو نبند.
- **بکاپ خودکار:** از همین صفحه روشنش کن؛ فایل برای همه‌ی ادمین‌ها در تلگرام ارسال میشه (اول باید به ربات `/start` زده باشن).

## 🚀 راه‌اندازی

### متغیرهای محیطی

| متغیر | لازم؟ | توضیح |
|---|---|---|
| `BOT_TOKEN` | ✅ | توکن از @BotFather |
| `ADMIN_IDS` | ✅ | آیدی عددی ادمین‌ها، با کاما |
| `WEBHOOK_SECRET` | ✅ | یک رشته‌ی تصادفی بلند (حروف انگلیسی/عدد/خط تیره) |
| `PANEL_PASSWORD` | اختیاری | ورود به پنل وب با رمز (ورود با `/panel` همیشه فعاله) |
| `SESSION_SECRET` | اختیاری | کلید امضای نشست‌ها |
| `NO_BUTTON_STYLE` | اختیاری | مقدار `1` = خاموش کردن رنگ دکمه‌ها |
| `CF_API_TOKEN`, `CF_ACCOUNT_ID` | اختیاری، Cloudflare | آمار مصرف در پنل (توکن با دسترسی *Account Analytics: Read*) |
| `D1_DATABASE_ID`, `KV_NAMESPACE_ID`, `CF_SCRIPT_NAME` | اختیاری، Cloudflare | شناسه‌ها برای آمار مصرف؛ توی `[vars]` فایل `wrangler.toml` |
| `DATA_DIR`, `PUBLIC_URL`, `AUTO_WEBHOOK` | اختیاری، Railway | مسیر Volume (پیش‌فرض `/data`)، آدرس عمومی (خودکار)، `0` = وبهوک خودکار خاموش |

نمونه‌ی کامل: فایل `.env.example`.

### روش اول — Cloudflare Workers
```bash
cd vpnbot-panel
wrangler d1 create config-sales-bot-db
# database_id رو داخل wrangler.toml بذار
wrangler d1 execute config-sales-bot-db --remote --file=./schema.sql
wrangler secret put BOT_TOKEN
wrangler secret put ADMIN_IDS
wrangler secret put WEBHOOK_SECRET
wrangler secret put PANEL_PASSWORD     # اختیاری
wrangler deploy
```
بعد آدرس Worker + `/panel` رو باز کن، وارد شو و از **«سیستم و استقرار ← تنظیم وبهوک»** وبهوک رو ست کن. (روش دستی: `https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://<worker>.workers.dev/webhook/<WEBHOOK_SECRET>&allowed_updates=["message","callback_query","chat_member"]`)

**KV (اختیاری):**
```bash
wrangler kv namespace create CACHE
```
بخش `[[kv_namespaces]]` در `wrangler.toml` رو از کامنت دربیار و `id` رو بذار، بعد دوباره `wrangler deploy`.

**آمار مصرف (اختیاری):**
```bash
wrangler secret put CF_API_TOKEN
wrangler secret put CF_ACCOUNT_ID
```
و `D1_DATABASE_ID` (و اگه KV داری `KV_NAMESPACE_ID`) رو در `[vars]` فایل `wrangler.toml` پر کن.

**بکاپ خودکار:** `wrangler.toml` یه Cron هر ۶ ساعت داره؛ از پنل روشن/خاموش و بازه‌اش رو انتخاب کن.

### روش دوم — Railway
1. پروژه رو به یک ریپوی GitHub بفرست ← Railway ← **New Project ← Deploy from GitHub repo**.
2. یک **Volume** بساز و روی مسیر `/data` وصلش کن. **بدونش دیتابیس با هر دیپلوی پاک میشه.**
3. در **Variables**: `BOT_TOKEN`، `ADMIN_IDS`، `WEBHOOK_SECRET`، `PANEL_PASSWORD`.
4. در **Settings ← Networking** روی *Generate Domain* بزن. وبهوک موقع بالا اومدن خودکار تنظیم میشه.
5. آدرس دامنه + `/panel` رو باز کن.

نکته‌ها: Node نسخه‌ی ۲۲٫۱۳ یا بالاتر لازمه (در `nixpacks.toml` تنظیم شده) و هیچ پکیج npm نیاز نیست. دیتابیس یه فایل SQLite روی Volume است. اجرای محلی:
```bash
BOT_TOKEN=... ADMIN_IDS=... WEBHOOK_SECRET=... PANEL_PASSWORD=... node railway/server.js
```
(پشت NAT برای وبهوک تلگرام به آدرس HTTPS عمومی نیاز داری؛ `AUTO_WEBHOOK=0` بذار و دستی ست کن.)

### انتقال بین Cloudflare و Railway
روی مبدا از «بکاپ و بازیابی» بکاپ بگیر، روی مقصد همون صفحه فایل رو با حالت «جایگزینی کامل» بازیابی کن. بعد وبهوک رو روی مقصد ست کن (و روی مبدا حذفش کن تا دو سرور هم‌زمان جواب ندن).

### ارتقا از نسخه‌های قبلی
دیتابیس این نسخه با قبلی‌ها سازگاره و جدول جدیدی نداره. فقط هر کدوم از فایل‌های زیر که **قبلا اجرا نکردی** رو به ترتیب و **هرکدوم فقط یک بار** اجرا کن، بعد دیپلوی:
```bash
wrangler d1 execute config-sales-bot-db --remote --file=./migration_v2.sql   # اتصال به پنل‌ها
wrangler d1 execute config-sales-bot-db --remote --file=./migration_v3.sql   # حجم دلخواه
wrangler d1 execute config-sales-bot-db --remote --file=./migration_v4.sql   # اشتراک قبلی + QR
wrangler d1 execute config-sales-bot-db --remote --file=./migration_v5.sql   # دسته‌بندی محصولات (اختیاری؛ ربات خودش جدول رو می‌سازه)
wrangler deploy
```
(اگه یکی رو دوباره اجرا کنی ارور `duplicate column` می‌ده؛ بی‌خطره و یعنی قبلا اجرا شده. دقت کن `--remote` و `--file` **دو خط تیره** دارن.) قوانین، رنگ‌ها و تنظیمات ظاهر نیاز به مایگریشن ندارن. روی Railway همه‌چیز خودکاره.

## ⚠️ نکته‌های مهم

### ۱) پنل VPN باید روی «دامنه با SSL معتبر» باشه، نه IP (فقط Cloudflare)
Cloudflare Workers به آدرس IP خام وصل نمیشه (خطای ۱۰۰۳) و طبق منابعی که پیدا کردم پورت‌های غیراستاندارد (مثل ۸۰۰۰/۲۰۵۳) رو هم ممکنه نادیده بگیره. پنل رو روی یه دامنه/ساب‌دامین، پورت **۴۴۳** و SSL واقعی بذار (Nginx/Caddy یا Cloudflare Tunnel رایگان). روی Cloudflare افزودن IP رد میشه؛ روی **Railway** اتصال به IP هم ممکنه.

### ۲) محدودیت‌های پلن رایگان Worker (فقط Cloudflare)
- هر درخواستِ ورودی حداکثر ~۵۰ تماس خروجی (تلگرام/پنل/دیتابیس) و حدود ۱۰ms زمان CPU داره.
- ساخت QR حدود ۳–۴ms CPU می‌گیره (اندازه‌گیری شده)؛ اگه فروشت زیاد شد یا به خطای CPU خوردی، پلن پولی Workers (حدود ۵ دلار در ماه) رو بگیر یا QR رو از «🔎 اشتراک قبلی و QR» خاموش کن.
- **پیام همگانی:** دستور متنی داخل ربات روی پلن رایگان فقط برای حدود ۴۵ نفر اول کار می‌کنه. **از پنل وب** پیام همگانی تکه‌تکه (۳۰ نفر در هر درخواست) فرستاده میشه و برای کاربر بیشتر هم کار می‌کنه؛ فقط تا پایان کار پنجره رو نبند. روی Railway این محدودیت Worker وجود نداره (سرعت ارسال رو صف تلگرام کنترل می‌کنه).
- سقف‌های KV پلن رایگان: ۱۰۰ هزار خواندن و **۱۰۰۰ نوشتن** در روز؛ بهینه‌ساز طوری نوشته شده که فقط موقع تغییر تنظیمات بنویسه.

### ۳) رنگ دکمه‌ها فقط روی تلگرام به‌روز دیده میشه
`style` از فوریه ۲۰۲۶ توسط تلگرام اضافه شده؛ کلاینت‌های قدیمی‌تر دکمه معمولی می‌بینن. اگه تلگرام استایل رو نپذیره ربات خودش بدون استایل دوباره می‌فرسته. برای خاموش کردن کامل رنگ‌ها: متغیر `NO_BUTTON_STYLE` با مقدار `1`.

### ۴) روی Railway حتما Volume وصل کن
بدون Volume روی `/data`، دیتابیس داخل کانتینر می‌مونه و با هر دیپلوی/ری‌استارت پاک میشه. صفحه‌ی «بهینه‌ساز و مصرف» هم در این حالت هشدار میده.

<details>
<summary><b>🔌 پنل‌ها (از داخل ربات)</b></summary>

از **پنل وب ← پنل‌های VPN** (فرم آماده) یا از داخل ربات: «🛠 پنل مدیریت ← 🔌 مدیریت پنل‌ها ← ➕ افزودن پنل». فرمت ربات: فیلدها با `|` جدا میشن (برای فیلد خالی `-`). بعد از ارسال، پیام حاوی رمز پاک میشه و تست اتصال اجرا میشه.

| پنل | فرمت |
|---|---|
| **Marzban** | `نام \| آدرس \| یوزرنیم \| پسورد \| آدرس ساب (اختیاری) \| پروتکل‌ها (اختیاری) \| flow (اختیاری)` |
| **PasarGuard** | `نام \| آدرس \| یوزرنیم \| پسورد \| آدرس ساب (اختیاری) \| آیدی گروه‌ها (اختیاری) \| flow (اختیاری)` |
| **3x-ui (سنایی)** | `نام \| آدرس کامل با مسیر مخفی \| یوزرنیم \| پسورد \| آیدی اینباند \| آدرس ساب \| توکن API (اختیاری) \| flow (اختیاری)` |

- **سنایی**: «آدرس ساب» همونیه که توی تنظیمات Subscription پنل هست (مثل `https://sub.example.com:2096/sub`). نسخه‌های قدیمی و جدید (CSRF، توکن API) پشتیبانی میشن؛ پروتکل‌های vless/vmess/trojan.
- **PasarGuard**: اگه گروه ندی کاربر جدید در همه گروه‌ها ساخته میشه. **Marzban**: پیش‌فرض پروتکل `vless`؛ برای Reality `flow` رو `xtls-rprx-vision` بذار.
- برای ربات یه **ادمین جدا** در هر پنل بساز (نه ادمین اصلی).

</details>

<details>
<summary><b>🛒 محصولات</b></summary>

از **پنل وب ← محصولات** (فرم آماده) یا داخل ربات «🛒 مدیریت محصولات»:
- **محصول عادی**: `نام | قیمت | مدت(روز)` → بعد «🔌 اتصال به پنل» و «📊 تنظیم حجم (گیگ)». بدون اتصال به پنل، کانفیگ‌ها دستی از انبار تحویل داده میشن.
- **🧮 حجم دلخواه**: `نام | حداقل گیگ | حداکثر گیگ | حداقل روز | حداکثر روز | قیمت هر گیگ | قیمت هر روز (اختیاری) | توضیحات`
  مثال: `حجم دلخواه | 5 | 200 | 30 | 365 | 2000 | 100` ← قیمت = (گیگ × ۲۰۰۰) + (روز × ۱۰۰). حتماً به یه پنل وصلش کن (تا وصل نشه برای مشتری نمایش داده نمیشه). قیمت همیشه لحظه‌ی پرداخت دوباره حساب میشه. ارقام فارسی هم پذیرفته میشن.
- **🆓 تست رایگان**: محصول با قیمت ۰ بساز، حجم/مدت کم بده و «تنظیم بعنوان تست رایگان» رو بزن.

</details>

<details>
<summary><b>🗂 دسته‌بندی محصولات</b></summary>

مثلا دو پنل داری: یکی «تانل‌دار» و یکی «بدون تانل».
1. ادمین: «🛒 مدیریت محصولات ← 🗂 دسته‌بندی‌ها ← ➕ افزودن دسته‌بندی» (مثلا `🚇 تانل‌دار` و `⚡️ بدون تانل`).
2. داخل هر دسته: «🔌 افزودن همه‌ی محصولات یک پنل» ← پنل رو انتخاب کن تا همه‌ی محصولاتش یکجا بره توی اون دسته. (یا برای هر محصول جدا: «لیست محصولات ← محصول ← 🗂 دسته‌بندی».)
3. مشتری موقع «🛍 خرید اشتراک» اول دسته‌ها رو می‌بینه و بعد پلن‌های همون دسته. محصولات بدون دسته زیر «📦 سایر» میان؛ اگه هیچ دسته‌ای نسازی همه‌چی مثل قبله.
- دسته‌ی غیرفعال‌شده (و محصولاتش) برای مشتری نمایش داده نمیشه. حذف دسته، محصولات رو پاک نمی‌کنه و فقط «بدون دسته» میشن.
- نیازی به اجرای دستی مایگریشن نیست؛ ربات جدول دسته‌بندی رو خودش می‌سازه (`migration_v5.sql` فقط برای اجرای دستی هست).

</details>

<details>
<summary><b>🔎 اشتراک‌های خارج از ربات</b></summary>

مشتری دکمه «🔎 استعلام/تمدید اشتراک قبلی» رو می‌زنه و **اسم اشتراکش** (یوزرنیم روی پنل) رو می‌فرسته. ربات همه‌ی پنل‌های فعال رو جستجو می‌کنه و **وضعیت، مصرف، باقی‌مانده و انقضا** رو نشون میده.
- **تمدید**: با پلن‌های عادی/فعالی که به **همون پنل** وصل کردی. ریست کامل: مصرف صفر و حجم/مدت جدید از امروز حساب میشه (روزهای باقی‌مانده‌ی قبلی اضافه نمیشن)؛ بقیه‌ی تنظیمات اکانت (flow، محدودیت IP، ...) دست‌نخورده می‌مونه. پرداخت: کیف‌پول یا کارت‌به‌کارت.
- **لینک ساب + QR** و تمدید، بعد از اتصال به حساب تلگرام مشتری، توی «📦 سرویس‌های من» هم میاد.
- ♻️ **تمدید با حجم دلخواه**: توی لیست پلن‌های تمدید اشتراک قبلی، محصول‌های «🧮 حجم دلخواه» که به همون پنل وصلن هم میان؛ مشتری حجم و مدت رو خودش انتخاب می‌کنه، قیمت خودکار حساب میشه و تمدید روی همون اکانت انجام میشه (پرداخت با کیف پول یا کارت‌به‌کارت).
- 🔐 **تایید مالکیت (پیش‌فرض: روشن)**: اسم اشتراک‌ها قابل حدس‌زدنه (مثل `ali1`) و لینک ساب مثل رمز عبوره؛ برای همین قبل از تمدید، مشتری باید **لینک اشتراک فعلیش** رو بفرسته (۳ تلاش، حداکثر ۱۲ استعلام در ۱۰ دقیقه). اگه می‌خوای فقط با اسم کار کنه: «🔎 اشتراک قبلی و QR ← خاموش کردن تایید مالکیت» (⚠️ ناامنه).
- اگه اشتراک روی پنل سنایی `subId` نداشته باشه، لینک ساب وجود نداره و با تایید مالکیت روشن امکان‌پذیر نیست.

</details>

<details>
<summary><b>📲 QR کد</b></summary>

همراه هر لینک (خرید، تمدید، تست) QR هم فرستاده میشه و زیر «سرویس‌های من» دکمه‌ی QR هست. QR **داخل خود Worker** ساخته میشه؛ لینک اشتراک هیچ‌وقت به سرویس بیرونی داده نمیشه.
خاموش/روشن: «🔎 اشتراک قبلی و QR».

</details>

<details>
<summary><b>🎨 شخصی‌سازی</b></summary>

- **قوانین**: «📜 قوانین» ← ویرایش متن (HTML مجازه؛ متن نامعتبر ذخیره نمیشه)، متن دکمه، روشن/خاموش. هر کاربر قبل از هر کاری یک‌بار با دکمه‌ی **سبز** می‌پذیره (کاربرهای قبلی هم یک‌بار می‌پذیرن). ادمین‌ها مسدود نمیشن.
- **دکمه‌ها**: «🎨 شخصی‌سازی دکمه‌ها» ← هر دکمه‌ی منو: تغییر متن، رنگ (آبی/سبز/قرمز/بدون رنگ) و **🔴 خاموش/روشن** (خاموش = از منو برداشته میشه و حتی با تایپ دستی/دکمه‌های قدیمی هم کار نمی‌کنه). رنگ دسته‌های دکمه‌های شیشه‌ای هم قابل تغییره.
- تغییر متن/رنگ کیبورد برای هر کاربر از `/start` بعدی (یا اولین پیام همگانی) اعمال میشه؛ متن‌های قبلی همچنان کار می‌کنن.

---

</details>

<details>
<summary><b>📣 گروه گزارش (تاپیک‌بندی خودکار)</b></summary>

1. یه گروه بساز و توی تنظیماتش **Topics** رو روشن کن (گروه میشه فروم).
2. ربات رو توی گروه اضافه کن و **ادمین** کن (دسترسی **Manage Topics** حتما).
3. توی گروه دستور `/setlog` رو بفرست (فقط ادمین‌های `ADMIN_IDS`). ربات تاپیک‌ها رو خودش می‌سازه. (از پنل وب ← تنظیمات ← گروه گزارش هم می‌تونی آیدی گروه رو بدی.)
4. دستورات دیگه: `/logtest` (پیام تست) و `/unsetlog` (قطع گزارش). از پنل ادمین هم «📣 گروه گزارش» همین کارها + روشن/خاموش کردن هر تاپیک رو داره.

تاپیک‌ها: 👤 کاربران (عضو جدید/خروج از کانال اجباری) — 🎁 تست رایگان — 🧾 رسیدها (عکس رسید + تایید/رد) — 🛒 خرید و تمدید (با کیف پول/کارت‌به‌کارت، شامل تمدید اشتراک قبلی) — 💰 کیف پول (شارژ) — ⚠️ خطاها (خطای ساخت سرویس/پنل، تموم شدن موجودی تست، خطای کد ربات).
- اگه یه تاپیک رو پاک کنی، دفعه‌ی بعد که گزارشی بیاد دوباره ساخته میشه.
- اگه گروه فروم نباشه یا دسترسی نداشته باشه، گزارش‌ها بدون تاپیک توی خود گروه میان.
- لینک اشتراک/کانفیگ مشتری توی گزارش‌ها نمیاد.
- پیام‌های عادی توی گروه‌ها نادیده گرفته میشن؛ ربات فقط دستورات بالا رو از ادمین‌ها می‌پذیره.

</details>

<a name="security"></a>
## 🔐 امنیت و محدودیت‌ها

### امنیت
- توکن‌ها و رمزها رو هیچ‌جا (حتی چت‌ها) منتشر نکن؛ هر توکنی که لو رفته رو عوض کن (BotFather ← Revoke، توکن API کلادفلر).
- اطلاعات ورود پنل‌های VPN داخل دیتابیس خودت (D1 یا SQLite) ذخیره میشه (متن ساده) و داخل فایل بکاپ هم هست — برای همین برای ربات ادمین جدا بساز و بکاپ‌ها رو امن نگه دار. پنل وب توی صفحه‌ها و لیست‌ها رمز و توکن پنل‌های VPN رو نشون نمیده (فقط «تنظیم شده» می‌بینی)؛ تنها جایی که این اطلاعات به مرورگر میرسه خود فایل بکاپه.
- فقط آیدی‌های `ADMIN_IDS` (لینک `/panel`) یا دارنده‌ی `PANEL_PASSWORD` به پنل وب و مدیریت ربات دسترسی دارن. کوکی نشست `HttpOnly` و `SameSite=Strict` است (روی HTTPS `Secure` هم میشه)، درخواست‌های تغییر‌دهنده‌ی پنل هدر و Origin رو چک می‌کنن، صفحه CSP و `X-Frame-Options` دارد و لینک ورود فقط یک‌بار قابل استفاده‌ست.
- هر سفارش قفل اتمیک داره (دوبار «تایید» دو سرویس نمی‌سازه) و کسر کیف‌پول اتمیکه.
- از `PANEL_PASSWORD` قوی و یکتا استفاده کن و پنل رو فقط روی HTTPS باز کن.

### محدودیت‌های شناخته‌شده
- API پنل‌های VPN رو از کد کتابخانه‌های رسمی‌شون استخراج و با پنل‌های **شبیه‌سازی‌شده** تست کردم؛ **روی پنل واقعی تو هنوز تست نشده**. اگه خطا داد، پیام خطا (به فارسی) برای ادمین میاد؛ همون رو بفرست.
- **پنل وب:** روی Node با داده‌ی آزمایشی و روی مسیر Cloudflare با تلگرام و دیتابیس شبیه‌سازی‌شده تست شده؛ **روی Cloudflare/Railway/تلگرام واقعی هنوز تست نشده.** همچنین کوئری‌های آمار مصرف کلادفلر (GraphQL) از روی مستندات نوشته شده و اگه بخشی خطا بده، پیامش همون‌جا نمایش داده میشه.
- فونت وزیرمتن از CDN (jsdelivr) لود میشه؛ اگه در دسترس نباشه از فونت‌های سیستم استفاده میشه.
- آمار کلادفلر بر اساس UTC و با چند دقیقه تاخیره و هر ۵ دقیقه یک‌بار گرفته میشه.
- نسخه‌ی Railway از ماژول `node:sqlite` نود استفاده می‌کنه که هنوز رسما «experimental» است (هشدار موقع اجرا عادیه).
- جستجوی اشتراک سنایی کل اینباندها رو می‌خونه؛ روی پنل‌های خیلی بزرگ (هزاران کلاینت) ممکنه از سقف CPU پلن رایگان Cloudflare رد بشه.
- «سرویس‌های من» مصرف زنده رو برای ۵ سرویس آخر (+۵ اشتراک قبلی) می‌گیره.
- shadowsocks در سنایی برای *ساخت* کاربر جدید پشتیبانی نمیشه (تمدید اشتراک موجود شدنیه).
- یادآوری خودکار انقضا/اتمام حجم هنوز نیست.

### توسعه‌ی ظاهر پنل
کد رابط در `src/web/panel.part1.html` (استایل)، `panel.part2.html` و `panel.part3.html` (منطق) است. بعد از هر تغییر:
```bash
node scripts/build-ui.mjs   # فایل src/web/ui.generated.js رو می‌سازه
```
