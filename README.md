## 🖥 پنل وب

آدرس پنل = آدرس Worker یا Railway + `/panel` (مثلا `https://xxx.workers.dev/panel`). فارسی و راست‌به‌چین، تم تیره و سازگار با موبایل (از منوی مرورگر می‌تونی به صفحه‌ی اصلی گوشی اضافه‌اش کنی).

### ورود
1. **از داخل ربات:** به‌عنوان ادمین دستور `/panel` رو بفرست؛ لینک ورود **یک‌بار مصرف و ۵ دقیقه‌ای** می‌گیری.
2. **با رمز:** متغیر `PANEL_PASSWORD` رو ست کن و رمز رو توی صفحه‌ی ورود بزن (بعد از ۸ تلاش اشتباه، ۱۰ دقیقه قفل میشه).

نشست ۷ روز اعتبار داره. برای باطل‌کردن همه‌ی نشست‌ها `SESSION_SECRET` رو عوض کن (اگه نذاشتی‌اش، `PANEL_PASSWORD` رو).

### بخش‌ها
| بخش | کارها |
|---|---|
| **داشبورد** | فروش امروز و ۷/۳۰ روز، کاربران، نمودار ۱۴ روزه، رسیدهای در انتظار (تایید/رد سریع)، هشدار موجودی و مصرف منابع |
| **پنل‌های VPN** | افزودن/ویرایش Marzban، PasarGuard و 3x-ui، تست اتصال |
| **محصولات و تعرفه‌ها** | پلن ثابت، حجم دلخواه، تست رایگان، دسته‌بندی، انبار کانفیگ (افزودن گروهی) |
| **رسیدها و سفارش‌ها** | فیلتر و جستجو، دیدن عکس رسید، تایید (تحویل خودکار سرویس) و رد |
| **بهینه‌ساز و مصرف** | آمار کش و KV؛ روی Cloudflare مصرف Worker/KV/D1؛ روی Railway منابع سرور و صف درخواست‌ها |
| **کاربران و کیف‌پول** | جستجو، مسدود/آزاد، افزایش/کاهش موجودی (با اطلاع به کاربر)، پیام تکی، **پیام همگانی** |
| **بکاپ و بازیابی** | دانلود بکاپ (JSON یا SQL فشرده)، ارسال به تاپیک «💾 بکاپ»، بازیابی |
| **سیستم و استقرار** | وضعیت ربات و وبهوک، تنظیم/حذف وبهوک، چک‌لیست متغیرها |
| **تنظیمات ربات** | شماره کارت، متن پشتیبانی/آموزش، درصد زیرمجموعه، دکمه‌ها و رنگ‌ها، قوانین، متن خوش‌آمد، گردونه، کانال اجباری، گروه گزارش |

### 📢 پیام همگانی از پنل
از همون موتور خود ربات استفاده می‌کنه (پیش‌نمایش برای ادمین، گزارش موفق/بلاک‌کرده/ناموفق، توقف، ادامه بعد از ری‌استارت). توی پنل نوار پیشرفت زنده می‌بینی. روی **Cloudflare** تا وقتی پنجره باز باشه خود پنل هر چند ثانیه یک «تیک» ۴۰ نفره می‌زنه (سریع‌تر از Cron هر دقیقه)، و اگه ببندی‌اش Cron ادامه می‌ده.

### ⚡ بهینه‌ساز
- **هر دو پلتفرم:** همه‌ی تنظیمات ربات با «یک» کوئری خونده و ۱۵ ثانیه توی حافظه کش میشه (به‌جای یک کوئری برای هر تنظیم). اگه **KV** وصل باشه یه نسخه‌ی مشترک هم اونجا هست که فقط موقع تغییر تنظیمات نوشته میشه (سقف نوشتن KV پلن رایگان ۱۰۰۰ بار در روزه). KV **اختیاریه**. روی Railway KV داخل همون فایل SQLite ساخته میشه.
- **فقط Railway:** صف نرخ تلگرام (~۲۵ پیام در ثانیه + فاصله برای هر چت) با تلاش مجدد خودکار روی خطای 429، حذف آپدیت تکراری تلگرام، صف ترتیبی برای هر کاربر، ادغام درخواست‌های GET هم‌زمان و تایم‌اوت ۲۵ ثانیه‌ای.

### 💾 بکاپ از پنل
| فرمت | ویژگی |
|---|---|
| **JSON** | روی هر پلتفرمی از همین پنل بازیابی میشه (جایگزینی کامل یا ادغام). جدول `state` فقط اسم‌های دلخواه سرویس‌ها رو نگه می‌داره |
| **SQL فشرده (`.sql.gz`)** | همون فرمت بکاپ شبانه؛ روی Railway از پنل بازیابی میشه (و با `/restore/<WEBHOOK_SECRET>`)، روی Cloudflare با `wrangler d1 execute` |

قبل از هر بازیابی، یک بکاپ ایمنی از وضعیت فعلی دانلود میشه. دانلود و بازیابی توی تاپیک «💾 بکاپ» گروه گزارش لاگ میشن. **فایل بکاپ شامل رمز پنل‌های VPN هم هست؛ جای امن نگهش دار.**

### آمار مصرف Cloudflare (اختیاری)
```powershell
wrangler secret put CF_API_TOKEN     # توکن با دسترسی Account Analytics: Read
wrangler secret put CF_ACCOUNT_ID
```
و `D1_DATABASE_ID` (و اگه KV داری `KV_NAMESPACE_ID`) رو در `[vars]` فایل `wrangler.toml` پر کن. KV رو هم با `wrangler kv namespace create CACHE` بساز و بخش `[[kv_namespaces]]` رو از کامنت دربیار.

<a name="important"></a>
## ⚠️ نکته‌های مهم

### ۱) پنل باید روی «دامنه با SSL معتبر» باشه، نه IP
Cloudflare Workers به آدرس IP خام وصل نمیشه (خطای ۱۰۰۳) و طبق منابعی که پیدا کردم پورت‌های غیراستاندارد (مثل ۸۰۰۰/۲۰۵۳) رو هم ممکنه نادیده بگیره.
پنل رو روی یه دامنه/ساب‌دامین، پورت **۴۴۳** و SSL واقعی بذار (Nginx/Caddy یا Cloudflare Tunnel رایگان). ربات و پنل وب IP رو موقع افزودن رد می‌کنن (روی Railway هم) و بعد از ذخیره «تست اتصال» می‌زنی.

### ۲) محدودیت‌های پلن رایگان Worker
- هر درخواستِ ورودی حداکثر ~۵۰ تماس خروجی (تلگرام/پنل/دیتابیس) و حدود ۱۰ms زمان CPU داره.
- ساخت QR حدود ۳–۴ms CPU می‌گیره (اندازه‌گیری شده) و روی پلن رایگان جا میشه؛ اگه فروشت زیاد شد یا به خطای CPU خوردی، پلن پولی Workers (حدود ۵ دلار در ماه) رو بگیر یا QR رو از «🔎 اشتراک قبلی و QR» خاموش کن.
- **پیام همگانی**: روی **Railway/سرور** بدون سقف و با سرعت ~۲۵ پیام در ثانیه تا آخر ارسال میشه (حتی اگه وسطش ری‌استارت بشه ادامه می‌ده). روی **Cloudflare رایگان** هر دقیقه ۴۰ نفر (سقف ۵۰ تماس خروجی در هر اجرا) ارسال میشه و Cron هر دقیقه بقیه رو ادامه می‌ده؛ یعنی ۱۰۰۰ کاربر ≈ ۲۵ دقیقه. از **پنل وب** روی Cloudflare سریع‌تر هم میشه (پنل خودش تیک می‌زنه). روی هر دو: پیش‌نمایش برای ادمین، گزارش موفق/بلاک‌کرده/ناموفق، دکمه‌ی «⛔ توقف ارسال»، و کاربرهای مسدودشده پیام نمی‌گیرن.

### ۳) رنگ دکمه‌ها فقط روی تلگرام به‌روز دیده میشه
`style` از فوریه ۲۰۲۶ توسط تلگرام اضافه شده؛ کلاینت‌های قدیمی‌تر دکمه معمولی می‌بینن. اگه تلگرام استایل رو نپذیره ربات خودش بدون استایل دوباره می‌فرسته.
برای خاموش کردن کامل رنگ‌ها: `wrangler secret put NO_BUTTON_STYLE` با مقدار `1`.

## 🚀 راه‌اندازی سریع

### نصب از صفر
```powershell
cd config-sales-bot
wrangler d1 create config-sales-bot-db
# database_id رو داخل wrangler.toml بذار
wrangler d1 execute config-sales-bot-db --remote --file=./schema.sql
wrangler secret put BOT_TOKEN
wrangler secret put ADMIN_IDS
wrangler secret put WEBHOOK_SECRET
wrangler secret put PANEL_PASSWORD   # اختیاری (ورود به پنل وب با رمز)
wrangler deploy
```
بعد آدرس Worker + `/panel` رو باز کن یا داخل ربات `/panel` بفرست. وبهوک رو از **پنل ← سیستم و استقرار ← تنظیم وبهوک** ست کن، یا دستی (یک‌بار):
```
https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://<worker>.workers.dev/webhook/<WEBHOOK_SECRET>&allowed_updates=["message","callback_query","chat_member"]
```

### ارتقا از نسخه‌های قبلی
هر کدوم از فایل‌های زیر که **قبلا اجرا نکردی** رو به ترتیب و **هرکدوم فقط یک بار** اجرا کن، بعد دیپلوی:
```powershell
wrangler d1 execute config-sales-bot-db --remote --file=./migration_v2.sql   # اتصال به پنل‌ها
wrangler d1 execute config-sales-bot-db --remote --file=./migration_v3.sql   # حجم دلخواه
wrangler d1 execute config-sales-bot-db --remote --file=./migration_v4.sql   # اشتراک قبلی + QR
wrangler d1 execute config-sales-bot-db --remote --file=./migration_v5.sql   # دسته‌بندی محصولات (اختیاری؛ ربات خودش جدول رو می‌سازه)
wrangler deploy
```
(اگه یکی رو دوباره اجرا کنی ارور `duplicate column` می‌ده؛ بی‌خطره و یعنی قبلا اجرا شده. دقت کن `--remote` و `--file` **دو خط تیره** دارن.)
قوانین، رنگ‌ها و تنظیمات ظاهر نیاز به مایگریشن ندارن.

### 🚂 اجرا روی Railway
همین کد روی Railway هم اجرا میشه (Node 22 + دیتابیس SQLite روی Volume؛ بدون هیچ وابستگی npm).

1. پروژه رو روی یک ریپوی **خصوصی** GitHub بذار (یا با `railway up`) و در Railway «Deploy from GitHub» بزن. فایل‌های `Dockerfile` و `railway.json` آماده‌ست.
2. توی **Variables**: `BOT_TOKEN`، `ADMIN_IDS`، `WEBHOOK_SECRET` (همون مقدارهایی که روی کلادفلر داری) و برای ورود با رمز به پنل وب `PANEL_PASSWORD`.
3. توی **Settings ← Volumes**: یک Volume با مسیر `/data` بساز. **بدون Volume با هر دیپلوی دیتابیس پاک میشه.**
4. توی **Settings ← Networking**: «Generate Domain». ربات خودش وبهوک رو روی این دامنه ست می‌کنه (اگه دامنه نداشته باشی با long polling کار می‌کنه).

بعد از دیپلوی: آدرس دامنه + `/panel`.

متغیرهای اختیاری: `PANEL_PASSWORD`، `SESSION_SECRET`، `BACKUP_TZ` (پیش‌فرض `Asia/Tehran`)، `BACKUP_HOUR` (پیش‌فرض `0` یعنی ۱۲ شب)، `BOT_MODE`، `PUBLIC_URL`، `DB_PATH`، `NO_BUTTON_STYLE` — نمونه توی `.env.example`.

### 🔁 انتقال از Cloudflare به Railway (با همون دیتا و تنظیمات)
بدون از دست رفتن پیام: تلگرام تا ۲۴ ساعت آپدیت‌هایی که وبهوک نداره رو نگه می‌داره و بعد از ست‌شدن وبهوک جدید تحویل میده.

1. **Railway رو آماده کن** (بخش بالا) ولی یک متغیر دیگه هم بذار: `BOT_MODE=standby` (فقط سرور HTTP بالا میاد؛ وبهوک ست نمیشه). آدرس `https://<دامنه‌ات>/health` باید `ok` بده.
2. **کلادفلر رو متوقف کن** (آپدیت‌ها توی صف تلگرام می‌مونن):
   ```
   https://api.telegram.org/bot<TOKEN>/deleteWebhook
   ```
3. **از D1 خروجی بگیر:**
   ```powershell
   wrangler d1 export config-sales-bot-db --remote --output=dump.sql
   ```
4. **توی Railway بازیابی کن** (`<WEBHOOK_SECRET>` همون مقدار قبلیه):
   ```powershell
   curl.exe -X POST --data-binary "@dump.sql" https://<دامنه‌ات>/restore/<WEBHOOK_SECRET>
   ```
   خروجی تعداد ردیف‌های هر جدول رو نشون میده. این دستور امنه و چندبار اجراش اشکالی نداره.
5. **متغیر `BOT_MODE` رو پاک کن** تا Railway دوباره دیپلوی بشه؛ وبهوک خودکار ست میشه و پیام‌های صف‌شده تحویل داده میشن.
6. تست: `/start` با ادمین، بعد «🛠 پنل مدیریت ← 💾 بکاپ دیتابیس (همین حالا)».

**برگشت به کلادفلر** (اگه مشکلی بود): وبهوک قدیمی رو دوباره ست کن (دستور `setWebhook` بالای همین README). دیتابیس D1 دست‌نخورده می‌مونه؛ چند روز نگهش دار.

نکته: اگه پنل‌هات فقط IP مشخصی رو قبول می‌کنن، IP خروجی Railway با کلادفلر فرق داره.

### 💾 بکاپ شبانه و بازیابی
- هر شب ساعت **۰۰:۰۰ (تهران)** یک فایل `backup-تاریخ_ساعت.sql.gz` توی تاپیک **«💾 بکاپ»** گروه گزارش فرستاده میشه. تاپیک خودکار ساخته میشه (برای گروه‌های جدید هم `/setlog` اون رو می‌سازه).
- اگه گروه گزارش وصل نباشه یا تاپیک بکاپ از «📊 گروه گزارش» خاموش باشه، فایل به پیوی ادمین‌ها میره.
- دستی: «🛠 پنل مدیریت ← 💾 بکاپ دیتابیس (همین حالا)» یا از **پنل وب ← بکاپ و بازیابی** (دانلود JSON/SQL یا ارسال به تاپیک).
- روی **Cloudflare** هم کار می‌کنه (Cron Trigger توی `wrangler.toml`، ۲۰:۳۰ UTC = ۰۰:۰۰ تهران).
- **بازیابی روی Railway:** فایل بکاپ (حتی همون `.gz`) رو با همون دستور مرحله ۴ بالا به آدرس `/restore/<WEBHOOK_SECRET>` بفرست. ردیف‌ها با `INSERT OR REPLACE` برمی‌گردن. از **پنل وب ← بکاپ و بازیابی** هم می‌تونی همین فایل (`.sql` / `.sql.gz`) رو روی Railway بازیابی کنی؛ روی Cloudflare پنل فایل **JSON** رو بازیابی می‌کنه.

«🛠 پنل مدیریت ← 🔌 مدیریت پنل‌ها ← ➕ افزودن پنل». فیلدها با `|` جدا میشن (برای فیلد خالی `-`). بعد از ارسال، پیام حاوی رمز پاک میشه و تست اتصال اجرا میشه.

| پنل | فرمت |
|---|---|
| **Marzban** | `نام \| آدرس \| یوزرنیم \| پسورد \| آدرس ساب (اختیاری) \| پروتکل‌ها (اختیاری) \| flow (اختیاری)` |
| **PasarGuard** | `نام \| آدرس \| یوزرنیم \| پسورد \| آدرس ساب (اختیاری) \| آیدی گروه‌ها (اختیاری) \| flow (اختیاری)` |
| **3x-ui (سنایی)** | `نام \| آدرس کامل با مسیر مخفی \| یوزرنیم \| پسورد \| آیدی اینباند \| آدرس ساب \| توکن API (اختیاری) \| flow (اختیاری)` |

- **سنایی**: «آدرس ساب» همونیه که توی تنظیمات Subscription پنل هست (مثل `https://sub.example.com:2096/sub`). نسخه‌های قدیمی و جدید (CSRF، توکن API) پشتیبانی میشن؛ پروتکل‌های vless/vmess/trojan.
- **PasarGuard**: اگه گروه ندی کاربر جدید در همه گروه‌ها ساخته میشه. **Marzban**: پیش‌فرض پروتکل `vless`؛ برای Reality `flow` رو `xtls-rprx-vision` بذار.
- برای ربات یه **ادمین جدا** در هر پنل بساز (نه ادمین اصلی).

</details>

<details>
<summary><b>🛒 محصولات</b></summary>

«🛒 مدیریت محصولات»:
- **محصول عادی**: `نام | قیمت | مدت(روز)` → بعد «🔌 اتصال به پنل» و «📊 تنظیم حجم (گیگ)». بدون اتصال به پنل، کانفیگ‌ها دستی از انبار تحویل داده میشن.
- **🧮 حجم دلخواه**: `نام | حداقل گیگ | حداکثر گیگ | حداقل روز | حداکثر روز | قیمت هر گیگ | قیمت هر روز (اختیاری) | توضیحات`
  مثال: `حجم دلخواه | 5 | 200 | 30 | 365 | 2000 | 100` ← قیمت = (گیگ × ۲۰۰۰) + (روز × ۱۰۰). حتماً به یه پنل وصلش کن (تا وصل نشه برای مشتری نمایش داده نمیشه). قیمت همیشه لحظه‌ی پرداخت دوباره حساب میشه. ارقام فارسی هم پذیرفته میشن.
- **🆓 تست رایگان**: محصول با قیمت ۰ بساز، حجم/مدت کم بده و «تنظیم بعنوان تست رایگان» رو بزن.

</details>

<details>
<summary><b>🗂 دسته‌بندی محصولات</b></summary>

مثلا دو پنل داری: یکی «تانل‌دار» و یکی «بدون تانل».
1. ادمین: «🛒 مدیریت محصولات ← 🗂 دسته‌بندی‌ها ← ➕ افزودن دسته‌بندی» (مثلا `🚇 تانل‌دار` و `⚡️ بدون تانل`).
2. داخل هر دسته: «🔌 افزودن همه‌ی محصولات یک پنل» ← پنل رو انتخاب کن تا همه‌ی محصولاتش یکجا بره توی اون دسته. (یا برای هر محصول جدا: «لیست محصولات ← محصول ← 🗂 دسته‌بندی».)
3. مشتری موقع «🛍 خرید اشتراک» اول دسته‌ها رو می‌بینه و بعد پلن‌های همون دسته. محصولات بدون دسته زیر «📦 سایر» میان؛ اگه هیچ دسته‌ای نسازی همه‌چی مثل قبله.
- دسته‌ی غیرفعال‌شده (و محصولاتش) برای مشتری نمایش داده نمیشه. حذف دسته، محصولات رو پاک نمی‌کنه و فقط «بدون دسته» میشن.
- نیازی به اجرای دستی مایگریشن نیست؛ ربات جدول دسته‌بندی رو خودش می‌سازه (`migration_v5.sql` فقط برای اجرای دستی هست).

</details>

<details>
<summary><b>🔎 اشتراک‌های خارج از ربات</b></summary>

مشتری دکمه «🔎 استعلام/تمدید اشتراک قبلی» رو می‌زنه و **اسم اشتراکش** (یوزرنیم روی پنل) رو می‌فرسته. ربات همه‌ی پنل‌های فعال رو جستجو می‌کنه و **وضعیت، مصرف، باقی‌مانده و انقضا** رو نشون میده.
- **تمدید**: با پلن‌های عادی/فعالی که به **همون پنل** وصل کردی. ریست کامل: مصرف صفر و حجم/مدت جدید از امروز حساب میشه (روزهای باقی‌مانده‌ی قبلی اضافه نمیشن)؛ بقیه‌ی تنظیمات اکانت (flow، محدودیت IP، ...) دست‌نخورده می‌مونه. پرداخت: کیف‌پول یا کارت‌به‌کارت.
- **لینک ساب + QR** و تمدید، بعد از اتصال به حساب تلگرام مشتری، توی «📦 سرویس‌های من» هم میاد.
- ♻️ **تمدید با حجم دلخواه**: توی لیست پلن‌های تمدید اشتراک قبلی، محصول‌های «🧮 حجم دلخواه» که به همون پنل وصلن هم میان؛ مشتری حجم و مدت رو خودش انتخاب می‌کنه، قیمت خودکار حساب میشه و تمدید روی همون اکانت انجام میشه (پرداخت با کیف پول یا کارت‌به‌کارت).
- 🔐 **تایید مالکیت (پیش‌فرض: روشن)**: اسم اشتراک‌ها قابل حدس‌زدنه (مثل `ali1`) و لینک ساب مثل رمز عبوره؛ برای همین قبل از تمدید، مشتری باید **لینک اشتراک فعلیش** رو بفرسته (۳ تلاش، حداکثر ۱۲ استعلام در ۱۰ دقیقه). اگه می‌خوای فقط با اسم کار کنه: «🔎 اشتراک قبلی و QR ← خاموش کردن تایید مالکیت» (⚠️ ناامنه).
- اگه اشتراک روی پنل سنایی `subId` نداشته باشه، لینک ساب وجود نداره و با تایید مالکیت روشن امکان‌پذیر نیست.

</details>

<details>
<summary><b>📲 QR کد</b></summary>

همراه هر لینک (خرید، تمدید، تست) QR هم فرستاده میشه و زیر «سرویس‌های من» دکمه‌ی QR هست. QR **داخل خود Worker** ساخته میشه؛ لینک اشتراک هیچ‌وقت به سرویس بیرونی داده نمیشه.
خاموش/روشن: «🔎 اشتراک قبلی و QR».

</details>

<details>
<summary><b>🎨 شخصی‌سازی</b></summary>

- **قوانین**: «📜 قوانین» ← ویرایش متن (HTML مجازه؛ متن نامعتبر ذخیره نمیشه)، متن دکمه، روشن/خاموش. هر کاربر قبل از هر کاری یک‌بار با دکمه‌ی **سبز** می‌پذیره (کاربرهای قبلی هم یک‌بار می‌پذیرن). ادمین‌ها مسدود نمیشن.
- **👋 متن خوشامدگویی**: «👋 متن خوشامدگویی» ← دو متن جدا: **کاربر جدید** (بعد از ثبت‌نام) و **کاربر قبلی** (/start مجدد). پیش‌نمایش دارد و برای برگشت به پیش‌فرض بنویس `default`. HTML مجازه (متن نامعتبر ذخیره نمیشه). متغیرها: `{name}` اسم کاربر، `{username}` یوزرنیم، `{id}` آیدی عددی، `{bot}` اسم ربات. مثال: `سلام {name} عزیز 🌹 به {bot} خوش اومدی!` — بدون نیاز به مایگریشن. ترتیب برای کاربر جدید: قوانین ← عضویت اجباری (اگه فعال باشه) ← خوشامد.
- **مراحل خرید**: هر مرحله (دسته‌بندی ← پلن ← حجم ← مدت ← نام کانفیگ ← پرداخت) همون پیام قبلی رو ویرایش می‌کنه و دکمه‌ی «🔙 برگشت» داره. برای محصولات پنلی کاربر می‌تونه **اسم دلخواه کانفیگ** بده (فقط حروف انگلیسی/عدد/`_`، ۳ تا ۲۰ کاراکتر) یا «🎲 نام پیش‌فرض» رو بزنه؛ اگه اسم تکراری باشه خودکار یه پسوند تصادفی می‌گیره. بدون نیاز به مایگریشن.
- **سرویس‌های من**: اول لیست اسم سرویس‌ها میاد؛ با زدن روی هر کدوم صفحه‌ی جزئیات باز میشه (حجم کل/باقی‌مانده، روزهای باقی‌مانده، لینک اشتراک) با دکمه‌های: کانفیگ‌های تکی، QR، تمدید، آموزش اتصال، **تغییر نام نمایشی** (فقط داخل ربات؛ بدون مایگریشن) و برگشت.
- **دکمه‌ها**: «🎨 شخصی‌سازی دکمه‌ها» ← هر دکمه‌ی منو: تغییر متن، رنگ (آبی/سبز/قرمز/بدون رنگ) و **🔴 خاموش/روشن** (خاموش = از منو برداشته میشه و حتی با تایپ دستی/دکمه‌های قدیمی هم کار نمی‌کنه). رنگ دسته‌های دکمه‌های شیشه‌ای هم قابل تغییره.
- تغییر متن/رنگ کیبورد برای هر کاربر از `/start` بعدی (یا اولین پیام همگانی) اعمال میشه؛ متن‌های قبلی همچنان کار می‌کنن.

---

</details>

<details>
<summary><b>📣 گروه گزارش (تاپیک‌بندی خودکار)</b></summary>

1. یه گروه بساز و توی تنظیماتش **Topics** رو روشن کن (گروه میشه فروم).
2. ربات رو توی گروه اضافه کن و **ادمین** کن (دسترسی **Manage Topics** حتما).
3. توی گروه دستور `/setlog` رو بفرست (فقط ادمین‌های `ADMIN_IDS`). ربات تاپیک‌ها رو خودش می‌سازه.
4. دستورات دیگه: `/logtest` (پیام تست) و `/unsetlog` (قطع گزارش). از پنل ادمین هم «📣 گروه گزارش» همین کارها + روشن/خاموش کردن هر تاپیک رو داره.

تاپیک‌ها: 👤 کاربران (عضو جدید/خروج از کانال اجباری) — 🎁 تست رایگان — 🧾 رسیدها (عکس رسید + تایید/رد) — 🛒 خرید و تمدید (با کیف پول/کارت‌به‌کارت، شامل تمدید اشتراک قبلی) — 💰 کیف پول (شارژ) — ⚠️ خطاها (خطای ساخت سرویس/پنل، تموم شدن موجودی تست، خطای کد ربات).
- اگه یه تاپیک رو پاک کنی، دفعه‌ی بعد که گزارشی بیاد دوباره ساخته میشه.
- اگه گروه فروم نباشه یا دسترسی نداشته باشه، گزارش‌ها بدون تاپیک توی خود گروه میان.
- لینک اشتراک/کانفیگ مشتری توی گزارش‌ها نمیاد.
- پیام‌های عادی توی گروه‌ها نادیده گرفته میشن؛ ربات فقط دستورات بالا رو از ادمین‌ها می‌پذیره.

</details>

<a name="security"></a>
## 🔐 امنیت و محدودیت‌ها

### امنیت
- توکن‌ها و رمزها رو هیچ‌جا (حتی چت‌ها) منتشر نکن؛ هر توکنی که لو رفته رو عوض کن (BotFather ← Revoke، توکن API کلادفلر).
- اطلاعات ورود پنل‌ها داخل D1 حساب خودت ذخیره میشه (متن ساده) — برای همین ادمین جدا بساز.
- فقط آیدی‌های `ADMIN_IDS` (لینک `/panel` در ربات) یا دارنده‌ی `PANEL_PASSWORD` به پنل وب و مدیریت ربات دسترسی دارن. کوکی نشست `HttpOnly` و `SameSite=Strict` است (روی HTTPS `Secure` هم میشه)، درخواست‌های تغییر‌دهنده‌ی پنل هدر و Origin رو چک می‌کنن، صفحه CSP و `X-Frame-Options` داره و لینک ورود فقط یک‌بار قابل استفاده‌ست. پنل وب توی صفحه‌ها رمز و توکن پنل‌های VPN رو نشون نمیده (فقط «تنظیم شده»)؛ تنها جایی که به مرورگر میرسه فایل بکاپه. از `PANEL_PASSWORD` قوی استفاده کن و پنل رو فقط روی HTTPS باز کن؛ هر سفارش قفل اتمیک داره (دوبار «تایید» دو سرویس نمی‌سازه) و کسر کیف‌پول اتمیکه.

### محدودیت‌های شناخته‌شده
- API پنل‌ها رو از کد کتابخانه‌های رسمی‌شون استخراج و با پنل‌های **شبیه‌سازی‌شده** تست کردم؛ **روی پنل واقعی تو هنوز تست نشده**. اگه خطا داد، پیام خطا (به فارسی) برای ادمین میاد؛ همون رو بفرست.
- جستجوی اشتراک سنایی کل اینباندها رو می‌خونه؛ روی پنل‌های خیلی بزرگ (هزاران کلاینت) ممکنه از سقف CPU پلن رایگان رد بشه.
- «سرویس‌های من» مصرف زنده رو برای ۵ سرویس آخر (+۵ اشتراک قبلی) می‌گیره.
- shadowsocks در سنایی برای *ساخت* کاربر جدید پشتیبانی نمیشه (تمدید اشتراک موجود شدنیه).
- یادآوری خودکار انقضا/اتمام حجم هنوز نیست (با Cron Trigger قابل اضافه‌کردنه).
- **پنل وب:** روی Node با داده‌ی آزمایشی (حالت‌های webhook/polling/standby) و روی مسیر Cloudflare با دیتابیس و تلگرام شبیه‌سازی‌شده تست شده؛ **روی Cloudflare/Railway/تلگرام واقعی هنوز تست نشده.** کوئری‌های آمار مصرف کلادفلر (GraphQL) از روی مستندات نوشته شده؛ اگه بخشی خطا بده پیامش همون‌جا نمایش داده میشه.
- فونت وزیرمتن از CDN (jsdelivr) لود میشه؛ اگه در دسترس نباشه فونت سیستم استفاده میشه. آمار کلادفلر بر اساس UTC و با چند دقیقه تاخیره.
- نسخه‌ی Railway از `node:sqlite` نود استفاده می‌کنه که هنوز رسما «experimental» ـه.
- دانلود بکاپ SQL از پنل روی Cloudflare رایگان ممکنه به سقف CPU بخوره (برای دیتابیس‌های بزرگ)؛ بکاپ JSON بدون این مشکله.

### توسعه‌ی ظاهر پنل
کد رابط در `src/web/panel.part1.html` (استایل) و `panel.part2.html` / `panel.part3.html` (منطق) است. بعد از هر تغییر:
```bash
node scripts/build-ui.mjs   # فایل src/web/ui.generated.js رو می‌سازه
```
